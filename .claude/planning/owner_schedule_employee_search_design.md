# 사장 스케줄 직원 이름 검색 설계

## 목표

기본 스케줄과 일자별 조정 화면에서 직원이 많아져도 이름 일부를 입력해 원하는 직원의 편집 행을 즉시 찾을 수 있게 한다.

## 선택한 방식

### 입력 즉시 클라이언트 필터링

- 검색 버튼을 따로 누르지 않고 입력할 때마다 활성 직원 목록을 필터링한다.
- 이름 앞뒤 공백은 무시하고, 이름에 검색어가 포함되면 표시한다.
- 검색어가 비어 있으면 전체 활성 직원을 다시 표시한다.
- 검색은 화면에 표시할 행만 바꾸며 스케줄과 일자별 조정 상태는 직원 ID 기준으로 그대로 유지한다.

직원 목록은 현재 화면에서 이미 보유하고 있고 서버 요청이 필요하지 않으므로, 제출형 검색이나 별도 검색 API보다 즉시 필터링이 가장 짧고 예측 가능한 흐름이다.

## 화면 설계

- 검색창은 안내 영역과 편집표 사이의 검색 도구 영역에 둔다.
- 768px 이상에서는 편집표 우측에 맞춘 컴팩트한 폭을 사용한다.
- 768px 미만에서는 검색창을 전체 폭으로 확장한다.
- 검색 아이콘, `직원 이름 검색` 입력, 검색어 지우기 버튼으로 구성한다.
- 검색 결과가 없으면 편집표 헤더 아래에 `검색 결과가 없습니다.`를 표시한다.
- 기본 스케줄과 일자별 조정에서 같은 검색 UI와 동작을 사용한다.
- 모든 색상은 기존 `--color-*` 토큰을 사용하고 라이트·다크 모드를 함께 지원한다.

## 컴포넌트 경계

- `EmployeeScheduleManager.tsx`: 검색어 상태와 필터링된 활성 직원 목록을 소유하고 두 모드의 행 렌더링에 같은 목록을 사용한다.
- `EmployeeScheduleSearch.tsx`: 검색 입력, 아이콘, 지우기 버튼만 담당한다.
- `EmployeeScheduleSearch.module.css`: 검색 도구의 반응형 배치와 입력 스타일을 담당한다.
- `EmployeeScheduleTable.tsx`: 검색 결과가 없을 때 접근 가능한 빈 결과 행을 표시한다.
- `EmployeeScheduleTable.module.css`: 편집표 안 빈 결과 행의 레이아웃만 담당한다.

이 분리로 300줄에 가까운 `EmployeeScheduleManager.tsx`에 검색 UI 마크업과 스타일 책임을 추가하지 않는다.

## 데이터 흐름

1. 검색 입력값을 `employeeQuery` 상태에 저장한다.
2. 검색어의 앞뒤 공백을 제거하고 소문자로 정규화한다.
3. `activeEmployees` 중 정규화한 이름에 검색어가 포함된 직원만 `visibleEmployees`로 계산한다.
4. 기본 스케줄과 일자별 조정 모두 `visibleEmployees`를 렌더링한다.
5. 검색어를 지우면 기존 직원별 편집 상태를 유지한 채 전체 목록을 다시 표시한다.

## 접근성

- 입력에는 `직원 이름 검색` 접근 가능한 이름을 제공한다.
- 지우기 버튼에는 `직원 검색어 지우기` 접근 가능한 이름을 제공한다.
- 빈 결과 문구는 편집표의 실제 행과 셀 역할로 제공해 표 탐색 흐름을 유지한다.

## 검증

- 기본 스케줄에서 전체 4명 중 `이서윤`만 검색해 한 행만 표시되는지 확인한다.
- 일부 이름 `서`를 검색해 `이서윤`, `박서준` 두 행이 표시되는지 확인한다.
- 검색어 지우기 후 4개 행이 복원되고 기존 편집값이 유지되는지 확인한다.
- 일자별 조정에서도 동일하게 이름 검색이 적용되는지 확인한다.
- 일치하지 않는 이름 입력 시 빈 결과 안내와 0개 직원 행을 확인한다.
- 1440px, 768px, 390px에서 검색창과 편집표가 가로로 넘치지 않는지 확인한다.
- 라이트·다크 모드에서 입력, 아이콘, 지우기 버튼, 빈 결과 문구의 대비를 확인한다.

## 제외 범위

- 전화번호, 상태, 근무 요일을 이용한 검색
- 초성 검색과 오타 교정
- 서버 검색, 페이지네이션, 정렬
- 검색어 URL 저장 또는 화면 간 공유
