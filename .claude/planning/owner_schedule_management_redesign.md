# 사장 스케줄 관리 화면 재설계

## 목표

기본 스케줄과 일자별 조정 화면의 넓은 웹 영역을 행 단위 편집에 효율적으로 사용하고, 직원별 설정을 짧은 시선 이동으로 비교·수정할 수 있게 한다.

## 문제

- 현재 데스크톱 행은 `직원 130px / 설정 1fr / 시간 auto` 구조여서 설정과 시간이 화면 양 끝으로 벌어진다.
- 열 제목이 없어 요일·근무 상태·시간 입력의 관계를 한눈에 파악하기 어렵다.
- 전체 폭을 사용하지만 실제 정보 밀도는 낮고 오른쪽으로 긴 시선 이동이 필요하다.
- 기존 스케줄 컴포넌트와 CSS가 300줄에 가까워 단순 추가는 파일 크기 규칙을 위반한다.

## 설계

### 공통 원칙

- 기능과 데이터 흐름은 변경하지 않고 화면 구조와 정렬만 변경한다.
- 기본 스케줄과 일자별 조정은 같은 편집표 골격을 사용한다.
- 표 헤더는 `직원 / 근무 요일 또는 근무 여부 / 근무 시간 / 관리` 순서로 표시한다.
- 시간 입력과 관리 버튼은 설정 바로 다음 영역에 배치한다.
- 표 배경, 헤더, 보더, 텍스트는 기존 CSS 토큰만 사용한다.

### 1024px 이상

```text
┌ 직원 ─────┬ 근무 요일/근무 여부 ─────┬ 근무 시간 ─────────┬ 관리 ┐
│ 직원 정보 │ 월 화 수 목 금 토 일       │ 09:00 ~ 18:00      │ 삭제 │
│ 직원 정보 │ 근무 / 휴무                │ 16:00 ~ 22:00      │ 기본 │
└───────────┴───────────────────────────┴────────────────────┴──────┘
```

- 전체 콘텐츠 폭을 사용하는 표면 카드 안에 열 헤더와 직원 행을 둔다.
- 직원 행 높이와 열 시작점을 통일해 세로 비교가 가능하게 한다.
- 기본 스케줄 표는 요일 영역을 넓게, 일자별 조정 표는 근무 여부 영역을 작게 사용한다.
- 시간 셀은 관리 영역까지 걸치고, 시간 입력은 왼쪽에, 삭제·기본으로 버튼은 오른쪽에 정렬한다.
- 표의 최소 너비가 가용 폭보다 크면 표 내부만 가로 스크롤한다.

### 768px 이상 1024px 미만

- 표 헤더를 숨긴다.
- 직원 정보를 왼쪽 열에 두고, 요일·근무 여부와 시간 입력을 오른쪽에서 두 줄로 배치한다.
- 페이지 전체 가로 스크롤은 허용하지 않는다.

### 768px 미만

- 기존 직원별 세로 카드 흐름과 입력 순서를 유지한다.
- 새 표 헤더와 데스크톱 표면 스타일은 표시하지 않는다.
- 하단 내비게이션과 저장 버튼의 기존 동작은 변경하지 않는다.

## 컴포넌트 경계

- `EmployeeScheduleManager.tsx`: 기존 데이터와 이벤트를 유지하고 편집표 래퍼 및 행 식별 속성만 추가한다.
- `EmployeeScheduleTable.tsx`: 두 모드가 공유하는 표 헤더와 래퍼만 담당한다.
- `EmployeeScheduleTable.module.css`: 태블릿·데스크톱 편집표 레이아웃과 전체 폭 규칙을 담당한다.
- `EmployeeScheduleManager.module.css`: 기존 모바일 컨트롤과 행 스타일을 유지하고 중복 데스크톱 폭 규칙을 제거한다.

## 검증

- 변경 전 데스크톱 캡처에서 열 헤더 부재와 긴 설정-시간 간격을 기준으로 실패를 확인한다.
- 변경 후 기본 스케줄과 일자별 조정에서 열 헤더, 표면 카드, 행 정렬을 확인한다.
- 1440×900, 1024×768, 768×900, 390×844에서 페이지 가로 넘침을 검사한다.
- 라이트·다크 모드에서 표 헤더, 행 보더, 입력, 선택 상태 대비를 확인한다.
- 기본 스케줄 생성·요일·시간·삭제와 일자별 조정 날짜·근무/휴무·시간·기본 복귀 동작이 유지되는지 확인한다.
- 린트의 기존 범위 밖 오류는 분리하고, 빌드와 변경 파일 검증을 완료한다.

## 제외 범위

- 휴무 사유, 메모, 변경 건수와 같은 새 데이터 또는 기능
- 저장 로직과 mock 데이터 구조 변경
- 공용 테이블 컴포넌트 도입
- 다른 사장 페이지의 목록 디자인 변경
