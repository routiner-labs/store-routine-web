# 사장 스케줄 관리 웹 전체 폭 설계

## 목표

사장 페이지의 출근 현황에서 `+` 버튼으로 진입하는 기본 스케줄과 일자별 조정 화면이 웹 환경에서 왼쪽 사이드바를 제외한 콘텐츠 영역 전체를 사용한다.

## 현재 구조

- `/owner/attendance/schedule`과 `/owner/attendance/adjust`는 `EmployeeScheduleManager`를 공유한다.
- 두 화면의 본문은 `EmployeeScheduleManager.module.css`의 `.body`에서 `max-width: 860px`로 제한된다.
- 사장 공통 레이아웃은 웹에서 왼쪽 사이드바와 오른쪽 콘텐츠 영역으로 구성된다.
- 모바일에서는 같은 본문이 화면 폭보다 좁아 `max-width` 제한의 영향을 받지 않는다.

## 설계

- `768px` 이상 미디어쿼리에서 `.body`의 `max-width`를 해제한다.
- 기존 `width: 100%`와 반응형 좌우 여백 토큰은 유지한다.
- 기본 스케줄과 일자별 조정의 컴포넌트 구조, 상태, 저장 동작은 변경하지 않는다.
- 사장 공통 사이드바와 상단 구조는 유지한다.
- 모바일의 세로형 직원 행과 하단 내비게이션은 유지한다.
- 기존 CSS 토큰만 사용하므로 라이트 모드와 다크 모드 동작은 그대로 유지된다.

## 선택 근거

- 모든 화면에서 제한을 제거하는 방법보다 웹 전용 요구사항이 CSS에 명확히 드러난다.
- `1024px`부터 적용하는 방법과 달리 태블릿 웹 구간에서도 가용 콘텐츠 폭을 일관되게 사용한다.
- 공용 스케줄 컴포넌트의 스타일 한 곳만 수정하므로 두 화면에 동일하게 적용되고 변경 범위가 작다.

## 검증

- 변경 전 데스크톱에서 본문 폭이 `860px`로 제한되는 검증이 실패하는지 확인한다.
- 변경 후 `1280px` 이상 화면에서 본문이 사이드바 오른쪽 콘텐츠 폭을 채우는지 확인한다.
- 기본 스케줄과 일자별 조정 두 경로에서 같은 결과를 확인한다.
- 모바일 화면에서 기존 세로 레이아웃과 가로 스크롤 없음이 유지되는지 확인한다.
- 라이트 모드와 다크 모드에서 배경, 보더, 텍스트 대비가 유지되는지 확인한다.
- 린트와 프로덕션 빌드를 실행한다.

## 제외 범위

- 사이드바를 가리는 브라우저 전체화면 전환
- 스케줄 데이터 저장 방식 변경
- 직원 행 구조 또는 입력 UI 재설계
- 새로운 테스트 프레임워크 도입
