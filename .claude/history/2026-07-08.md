## 위 툴팁을 포털+fixed 방식으로 재작업 (잘림·호버 끊김 버그 수정)

### 문제와 수정 흐름
1. "문서함 카테고리 툴팁 아래가 잘린다" — 원인: `.advPanel`이 `overflow:hidden`이라 절대위치 자식은 z-index와 무관하게 잘림.
2. "위쪽 말고 아래쪽으로, z-index로 고쳐줘" — 진짜 원인(overflow:hidden 클리핑)은 z-index로 해결 불가. 근본 해결로 전환: 툴팁을 `document.body`에 포털로 렌더(기존 `EmployeeProfilePopup`/각종 팝업과 동일 패턴)하고 트리거의 `getBoundingClientRect()`로 계산한 좌표에 `position:fixed`로 배치 — overflow 조상과 무관하게 항상 트리거 바로 아래, 잘리지 않음.
   - 공용 훅 `src/lib/useHoverTooltip.ts` 신규: `anchorRef`(호버 대상에 붙일 ref, 제네릭으로 span/div 등 아무 요소나 지원) + `rect`(포털 위치/폭) + `anchorHandlers`/`tooltipHandlers`(mouseenter/leave)를 반환. `MultiSelectFilter`, `owner/documents`·`owner/requests`의 작성자 요약 뱃지 툴팁에서 공통 사용.
   - `react-hooks/refs` eslint 규칙이 훅이 반환한 객체를 구조분해 없이 `obj.anchorRef`처럼 멤버 접근하면 "렌더 중 ref 접근" 오탐을 냄 — 페이지 두 곳에서 즉시 구조분해(`const { anchorRef: authorAnchorRef, ... } = useHoverTooltip()`)해서 회피.
3. "기간 쪽 툴팁은 없애도 될 것 같다" — `DateRangeFilter`는 트리거 자체가 260px로 넓어져 잘림이 없으므로 호버 툴팁 기능을 완전히 제거(관련 상태·CSS 정리, 트리거를 원래의 단순 버튼 구조로 복귀).
4. "상태 툴팁에 마우스 이동 중 꺼진다" — 트리거~툴팁 사이 6px 간격이 죽은 영역이라 그 사이를 지날 때 hover가 끊기는 문제. `useHoverTooltip`에서 `top`을 트리거 바로 아래(간격 0)로 붙이고, 시각적 여백은 툴팁 쪽 `padding-top:6px`로 대체 — 호버 가능 영역이 끊김 없이 연결됨.
- 최종 상태: `MultiSelectFilter`(카테고리/유형/상태 전부 자동 적용), `owner/documents`·`owner/requests`의 작성자 요약 뱃지 툴팁 모두 포털+fixed+간격 없는 hover 브릿지 방식. `DateRangeFilter`(기간)만 호버 툴팁 없음.
